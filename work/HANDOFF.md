### Guiding Light update: steering + explicit detonation
Reference (https://wiki.playvalorant.com/en-us/Guiding_Light): HOLD FIRE steers direction and altitude toward the crosshair. Implemented: client sends `hg:1` (and fire:0) in the input message while LMB is held with a hawk in flight; server steerHawk turns hd toward the owner's aim at GUIDING.turn rad/s, and ignores gun fire while hg. Client local hawk uses the same rule (XGL.turn). **GUIDING.turn = 4 rad/s is NOT published anywhere (unsourced tunable). Mapping caveat: in this game E casts (no separate equip/fire), so LMB-while-hawk-flies = hold-fire; the wiki's "cannot hold if cast without hold" latch is not modelled, and Skye cannot shoot during the hawk's <=2 s flight.**
Detonation: server flash row for Skye lingers ~0.25 s with `dn:1` after the blind is applied (applied once); the client bursts only on dn:1 (exactly once, also on a late first snapshot), a drop without dn (owner death before pop removes the hawk; reset/clear) is silent. A late re-use packet right after the hawk's own end is ignored (0.25 s cast cooldown). Tests: server/test-skye-hawk-row.js (owner death, steering, dn, late reuse), work/test_skye_pop_client.cjs. Env note: server tests test-bot-ults, test-two-client-18, test-network fail identically on the base because public/worlds assets are missing here (not suite-green).

### Guiding Light: faithful equip/launch/hold sequence (supersedes the mapping caveat above)
The page already has the equip framework (XAB_EQ / xEqKey0): E equips (0.8 s draw), FIRE launches, then unequip 0.85 s + gun re-equip. Added: XAB_HOLD.Skye.e = "hawk": FIRE down at the launch keeps FIRE held (shoot wrapper keeps fireHeld for hold abilities); if FIRE is still down when the hawk is cast, RS.hk.hold = true and the ability stays in hand (xEqTick state "steer") with steering toward the crosshair; releasing FIRE, re-use (E), pop or flight end latches hold off and starts the unequip. A click launch never steers (wiki). Online: cast message carries hl (hold at launch), input carries hg (steering held; fire:0 so no gun shot), server latches via the first input after the cast (seq > seq0). Weapon use is blocked by the existing J.eq/fireAt framework, not by a Skye-only hack. Gaps: server fireAt unequip after a long hold starts at the cast, so the server is more lenient than the client for holds > 0.85 s; GUIDING.turn 4 rad/s is an unsourced approximation.
