# perf3 — online + offline lag, 2026-10-28 (lane-perf3, base origin/main 5456dcd)

User ask: keep iterating on lag in both offline and online games, online first. Rule for every change: the game must play
exactly the same (same routes, same collisions, same messages on the wire), only cheaper.

## How it was measured
`work/perf_online_profile.cjs` runs the real page (real three scene graph, native map loader + collision BVH, WebGL stubbed)
against the real game server (`server/src/worker.js` in-process via `server/tools/local-cluster.mjs`, production fog of war +
skins) plus one scripted second human, both clocks virtual at 60 Hz. It records the page frame, the snapshot handling, the
server tick (split into sim step / snapshot / fog view / send), bytes per second, GC, and a game-state signature: a hash of
every message the page received and of the page's entity positions every frame.

A/B: base = `5456dcd` (shadow worktree), tip = lane-perf3, run interleaved (base, tip, base, tip ...) on the same box,
five (Spike 5v5), seed 3, 10 s warm-up then 30 s measured. The box is shared with other lanes, so milliseconds are a noisy
CPU proxy; allocation, GC counts and the signature are reliable.

## What changed (all bit-identical answers)
- Server world queries (`server/src/bvh-fast.js`, `world.js`): allocation-free ports of three-mesh-bvh raycastFirst /
  shapecast / closestPointToSegment over the same buffers; integer floor-cell keys; nearValid on a grid. Was 3-5 MB/tick.
- Fog of war sight tests (`fog.js` pairSees): scratch buffers, rays through the world's ray state.
- Server A* (`path.js` searchFast): heap push / pop written inline (two closures per search before) and the heuristic via
  `hyp.js` hyp2 (Math.hypot as V8 computes it, bit for bit; V8's builtin copies its arguments into a new array, ~84 B a call).
- `bots.js` variedPath (every bot, every tick): hyp2.
- `spike.js` world.blocked: the live-barrier check is a loop (an `effects.some(e => ...)` closure per call before).
- `worker.js` wireRoundState: plain loops instead of `Object.fromEntries(Object.entries(...).map(...))`: 21.7 KB -> 3.1 KB
  per call (per human per batched snapshot), same JSON byte for byte.
- Page `netClean` (server_runtime.js): helpers hoisted out of it, all-good lists / maps kept as they came: 10.8 KB -> 1.3 KB
  per snapshot frame, same cleaned frames as the original on ~6000 mutated / junk frames.
- Page `nmBlocked` per-triangle test (nmTsn): the radius no longer passed as a boxed double: 15.8 B -> ~0 B per triangle.
- Page `nmPath` (offline bots' A*): push / pop / heuristic inline, Math.hypot written out bit for bit, numeric cache key: ~207 KB -> ~2 KB per uncached
  search (page-like context with the page's Math.hypot patch, Ascent), identical routes.

## Proposals (not done in this lane)
- Bandwidth: snapshots resend every unit row in full ~20x a second (42-45 KB/s down per player in a 5v5). A delta / dedupe
  of unchanged row fields would cut it substantially but changes the wire protocol (page and worker must deploy together,
  plus reconnect / resume paths). Left as a proposal per the lane rules.
- Shared motor (`vendor/valorant-feel.js` == `server/src/motor.cjs`): `step` builds its moveAxis / helper closures on every
  call and `leashOk` builds a `rim` array; together the biggest server allocation left (~100+ KB/tick) and also hot on the
  page (moveP, bots). Needs a motor change on both sides with a bit-identical movement check (motor==vendor gate).
- `spike.js` step: a fresh input object per unit per tick and `motor()`'s `{...input, x, z}` spread for bots.
